## Disposition of the three findings

1. **Nonproportional fitting: resolved.** `Fit` uses one scale factor for both dimensions, then calls `ClampPosition`, which changes only position. `Anchor` and `Tuck` fit first. Initial tuck capture, restore, hide preparation, and screen reconfiguration now reach proportional fitting. `Resize` already computes a bounded aspect-preserving size and now only clamps its position. The previous 800×450 into 600×400 example becomes 600×337.5. Handle width is bounded by the fitted window width as well as screen width. See [geometry, line 46](patches/personal/arcium-pip-native-controls-macos.patch:46). The new geometry test covers direct fitting, all corner anchors, and both tuck directions. I found no remaining independently clipped width/height path in these helpers or their placement callers.

2. **Topology changes exposing tucked video: resolved in source.** `ExteriorTuck` first calculates each candidate's final fitted frame, then removes the handle strip to obtain the hidden rectangle and checks that rectangle against every other display. This evaluates the actual vertical band after fitting and position clamping. It handles adjoining and offset displays, including a hidden rectangle reaching a display across a gap. The chosen placement is the nearest safe candidate to the preferred placement. On a normal finite display arrangement, the outermost edge in the requested direction supplies a safe candidate. Both initial tuck and screen reconfiguration call the same placement method. `_anchorDisplay` tracks the current tuck destination; `_restoreDisplay` remains the original display identity. Restore and hide preparation prefer that original display when it still exists, and fit to a remaining display otherwise. See [exterior placement, line 106](patches/personal/arcium-pip-native-controls-macos.patch:106), [native placement, line 1134](patches/personal/arcium-pip-native-controls-macos.patch:1134), and [screen changes, line 1206](patches/personal/arcium-pip-native-controls-macos.patch:1206). The new tests cover an added right neighbor and vertical fitting that would invalidate a pre-fit overlap check. They do not prove physical display reconfiguration or Spaces behavior.

3. **Interrupted scrub losing resume intent: resolved by removing the cause.** The action enum and adapter no longer contain seek-begin/end transport actions, `seek_was_playing_`, or `_resumeAfterSeek`. `beginSeek` only suspends local progress updates and emits interaction bookkeeping; `endSeek` restores local chrome/timer behavior. `kSeek` validates the fraction and duration and forwards `SeekTo`, with no Play, Pause, Toggle, or synthetic playback-state update. Hide still discards queued input and clears local drag state, but has no transport change to undo. See [local scrub lifecycle, line 1376](patches/personal/arcium-pip-native-controls-macos.patch:1376), [hide preparation, line 1500](patches/personal/arcium-pip-native-controls-macos.patch:1500), and [seek dispatch, line 1918](patches/personal/arcium-pip-native-controls-macos.patch:1918).

The scrub deletion is preferable to adding session ownership for pause/resume. The [design](docs/automatic-picture-in-picture-native-design.md) now explicitly allows playback to continue during scrubbing. There is no temporary pause to match to a later resume, no resume intent to lose on hide, and no delayed resume that can affect replacement media or override an explicit pause. Existing weak delivery and hide invalidation still serve their separate purpose of rejecting queued input. Explicit close continues through `CloseAndPauseIfAvailable`; this review does not claim that close should leave playback running.

The real Chromium native-host test expects zero Play, Pause, and Toggle calls and exactly six `SeekTo(60 seconds)` calls across playing/paused × completed, hide-before-end, and end-before-hide cases. It checks the displayed playback state too. That is relevant coverage of the old defect. “End queued” is now an ordering case only: there is no asynchronous seek-end transport action left to queue. These tests use native objects and a mocked controller, not physical slider tracking or a live decoder. Real media seeking, interruptions, and replacement remain runtime gates.
